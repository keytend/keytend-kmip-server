{{- $fullname := include "kmip.fullname" . }}
{{- $ns := .Release.Namespace }}
keytend-kmip-server {{ .Chart.AppVersion }}: an experimental KMIP test server, not for production use.

{{- if .Values.maintenance.enabled }}

MAINTENANCE: the server is stopped (0 replicas). Volumes, Secrets and backups are kept.
Start it again with maintenance.enabled=false.
{{- else }}

Clients connect to {{ $fullname }}.{{ $ns }}.svc:{{ .Values.service.ports.kmip }} (TTLV)
{{- if .Values.server.https.enabled }} and https://{{ $fullname }}.{{ $ns }}.svc:{{ .Values.service.ports.https }}/kmip (HTTPS){{ end }},
with a client certificate from the policy.
{{- if .Values.networkPolicy.enabled }} The NetworkPolicy admits only the peers in
networkPolicy.clients (by default: pods labelled access=keytend-kmip-server in
namespaces labelled kmip-client=true).
{{- end }}

Wait for the pod and check it:
  kubectl -n {{ $ns }} rollout status statefulset/{{ $fullname }}
{{- if .Values.tests.clientSecret }}
  helm test {{ .Release.Name }} -n {{ $ns }} --logs
{{- else }}
  (set tests.clientSecret to make `helm test` send a KMIP Query)
{{- end }}
{{- end }}
{{- if .Values.restore.from }}

RESTORE {{ .Values.restore.id }}: the init container installs {{ .Values.restore.from }} before the server starts:
  kubectl -n {{ $ns }} logs {{ $fullname }}-0 -c restore
Have a client read a known key, then remove restore.from and restore.id from your values.
The previous database stays in /data/pre-restore-{{ .Values.restore.id }}/.
{{- end }}
{{- if include "kmip.rotating" . }}
{{- if .Values.rotation.revert }}

REVERT: the init container puts back the pre-rotation database; the server uses
{{ .Values.rotation.previousMasterKeySecret }}. Then set masterKey.existingSecret={{ .Values.rotation.previousMasterKeySecret }} and remove rotation.*.
{{- else }}

ROTATION: the init container rotates the store from {{ .Values.rotation.previousMasterKeySecret }} to {{ .Values.masterKey.existingSecret }}:
  kubectl -n {{ $ns }} logs {{ $fullname }}-0 -c rotate-master-key
{{- if .Values.auditCheckpoint.enabled }}
Publish the new audit checkpoint before you remove rotation.previousMasterKeySecret:
  kubectl -n {{ $ns }} logs {{ $fullname }}-0 -c checkpoint > checkpoint.json
  kubectl -n {{ $ns }} create configmap {{ .Values.auditCheckpoint.configMap }} --from-file={{ .Values.auditCheckpoint.key }}=checkpoint.json --dry-run=client -o yaml | kubectl apply -f -
and copy checkpoint.json to your independent checkpoint store.
{{- end }}
Then remove rotation.previousMasterKeySecret. Keep the old Secret while /data/pre-rotation-*/ exists.
{{- end }}
{{- end }}
{{- if .Values.backup.enabled }}

Backups: CronJob {{ $fullname }}-backup ("{{ .Values.backup.schedule }}", keeps {{ .Values.backup.retain }}) into PVC {{ include "kmip.backupClaim" . }},
{{- if .Values.backup.preUpgradeHook.enabled }} and one before every upgrade and rollback{{ end }}. Run one now (each run needs a new Job name):
  kubectl -n {{ $ns }} create job --from=cronjob/{{ $fullname }}-backup {{ $fullname }}-backup-$(date -u +%Y%m%d-%H%M%S)
The PVC is in the cluster's failure domain: copy backups off it too (volumeHelper.enabled).
{{- else }}

Backups are off (backup.enabled=false).
{{- end }}
